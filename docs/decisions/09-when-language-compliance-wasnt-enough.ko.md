# 09 — When Language Compliance Wasn't Enough

[전체 사례](../../README.ko.md) · [English](09-when-language-compliance-wasnt-enough.md) · [이전: 08](08-fix-the-chunker-not-the-documents.ko.md)

**개발 날짜:** 2026-11-02.

**기록 유형과 근거 수준:** 개발 대화에 남은 사용자 요청·판단과 당시 실행 보고를 바탕으로 작성한 문서형 의사결정 기록이다. 원본 실험 코드, 고정 입력 파일, 응답 JSON과 호출 로그는 사용자 요청으로 삭제됐다. 아래 수치는 당시 보고값이며, 이 문서 작성에서 원본과 재대조하지 않았다. 코드 발췌본은 수록하지 않는다.

**결과:** 일부 후보에서 출력 언어는 개선됐지만 답변 내용, 근거 분류와 인용이 함께 채택 기준을 충족하지 못했다. 사용자는 시험한 모든 변경안을 폐기하고 기존 운영 생성 정책을 유지했다.

## 한국어 근거를 여러 언어의 질문으로 탐색

Synethos는 승인된 기록을 검색해 류승원의 경력, 프로젝트와 개발 판단을 설명하는 RAG 기반 인터랙티브 프로필 서비스다. 한국어 중심의 지식베이스를 사용하며, 당시 생성 프롬프트에는 한국어 표현을 우선한다는 설명과 기본적으로 질문 언어로 답하라는 규칙이 함께 있었다. 명시적인 다른 언어 요청도 허용했다.

사용자는 처음에는 한국어 질문에 한국어, 나머지 질문에 영어로 답하는 방식을 검토했다. 일본어·아랍어·타갈로그어 응답 사례를 살펴본 뒤에는 모델의 다국어 응답 능력을 유지하면서 질문 언어를 일관되게 따르는 방향으로 실험 목적을 정리했다.

문제의 대표 질문은 다음과 같았다.

> What is Synethos, and why was it created?

운영 방식에서는 이 영어 질문에 한국어로 정의와 제작 이유를 설명했다. 영어 응답을 명시하면 영어로 답하는 사례도 있었다. 영어 작성 능력, 기본 언어 선택, 명시적 요청 준수는 나누어 확인할 대상이었다.

## 검색을 고정하고 생성 단계의 언어 제어를 비교

실험은 로컬에서 수행했다. 기본 질문에는 승인된 Synethos 문서의 제품 식별·제작 이유·서비스 설명 3개 청크를 고정했다. 타갈로그어 복합 질문에는 Synethos, Codex Session Observatory와 개발 방식 문서 3개의 선택된 16개 청크를 사용했다. 질문별 근거 내용과 순서를 고정하고 검색·임베딩을 다시 실행하지 않았다.

분류 모델은 `gemini-3.1-flash-lite`, 생성 모델은 `gemini-3.5-flash-lite`였다. 생성 실험에는 저장된 설정의 모델 옵션과 응답 스키마를 사용했다. 응답의 `basis`와 `citations`는 애플리케이션이 요구하는 JSON 필드였다.

| 접근 | 변경과 비교 조건 | 당시 실행 보고 |
|---|---|---|
| 분류 단계에서 언어 결정 | 3.1 결과에 `responseLanguage`를 추가하고 BCP 47 태그를 검증해 3.5에 전달했다. 생성의 기존 언어 선택 지시와 한국어 우선 문구는 교체하고 다른 정책 텍스트는 유지했다. | 기존 영어 Baseline의 분류·생성 2회와 후보 6개 질문의 분류·생성 12회, 총 14회 완료. 후보 6개 모두 기대한 언어로 답했다. |
| 한국어 우선 문구만 제거 | 기존 질문 언어 규칙을 유지하고 한국어 우선 문구 133자만 제거했다. 저장된 영어 Baseline, 분류 결과와 동일 근거를 재사용했다. | 같은 영어 질문에 생성 6회. 영어 4회·한국어 2회였다. 실제 실행은 동일 영어 질문 반복이며 다국어 6문항 비교와 구분한다. |
| 기존 정책에 언어 지침 보강 | 한국어 우선 설명과 기존 언어 규칙을 유지했다. 질문·근거 언어를 구분하고 영어 질문에는 영어로 답하며 반환 전 언어를 확인하라는 지침만 추가했다. | 저장된 분류·근거를 재사용해 6개 질문에 생성 각 1회. 5개는 기대 언어, 아랍어 질문은 영어로 답했다. |

6개 질문은 한국어, 영어, 한국어 질문의 영어 응답 요청, 일본어, 아랍어, 타갈로그어 복합 질문이었다. 타갈로그어 질문은 두 프로젝트의 구체적인 설계 결정·문제·절충점과 AI 활용·검증·사람의 책임을 비교하고 직접 사실과 종합 해석을 구분하도록 요구했다.

첫 실험의 초기 실행은 분류 전송 7건이 공급자 HTTP 응답 없이 실패했다. 별도로 승인된 재실행의 완료 보고가 위 14회다. 각 완료 실험은 자동 재시도·Fallback·임베딩 호출 없이 수행됐다고 보고됐다. 첫 실험 이후에는 Baseline을 다시 호출하지 않았다.

## 언어가 맞아도 내용과 인용이 함께 유지되지는 않았다

저장된 영어 Baseline은 한국어로 답했지만 정의, 단편적인 기록의 한계, 흩어진 작업 기록을 모은 이유와 이름 유래를 포함했다. `basis: "records"`, `citations: ["S1", "S2", "S3"]`를 반환했고, 당시 검토에서는 핵심 사실이 제공 근거와 부합한다고 보고했다.

분류 단계에서 언어를 전달한 후보는 영어로 답했지만 정의 한 문장으로 끝나 제작 이유를 생략했다. 영어와 아랍어 응답은 `basis: "system"`, `citations: []`였다. 다른 기본 질문은 기록 인용을 유지했고, 타갈로그어 응답은 근거를 인용했지만 사실과 종합 해석의 구분이 부분적이었다.

한국어 우선 문구만 제거한 6회는 모두 `system`과 빈 인용을 반환했다. 4회는 제작 이유를 생략하거나 일반적인 서비스 목적만 설명했고, 2회는 제작 배경을 일부 포함했다. 영어 응답 자체도 일관되지 않았다.

기존 정책에 언어 지침을 보강한 실행에서는 다음을 관찰했다.

| 질문 | 답변 언어 | 내용·근거 분류·인용에 대한 당시 검토 |
|---|---|---|
| 영어 | 영어 | 정의·제작 이유·이름 유래를 포함했으나 `system`과 빈 인용을 반환했다. |
| 한국어 | 한국어 | 핵심 내용을 설명하고 `records`와 S1–S3를 유지했다. |
| 한국어 + 영어 응답 요청 | 영어 | 핵심 내용을 설명하고 `records`와 S1–S3를 유지했다. |
| 일본어 | 일본어 | 핵심 내용을 설명하고 `records`와 S1–S3를 유지했다. |
| 아랍어 | 영어 | 언어 규칙을 지키지 못했고 제작 이유와 인용이 빠졌다. |
| 타갈로그어 | 타갈로그어 | `records`와 인용은 유지했지만 절충점 비교와 사실·종합 구분은 부분적이었다. |

언어 지침 변경 외의 프롬프트 보존과 입력 동일성은 당시 오프라인 검사에서 확인됐다고 보고됐다. 지침 텍스트를 유지한 것과 모델이 그 지침을 지키는지는 별개의 검증이었다.

## 인용 출력과 실제 문맥 활용을 구분

`basis: "system"`은 모델이 반환한 근거 분류이고, `citations: []`는 인용을 반환하지 않았다는 관찰이다. 두 필드만으로 모델이 한국어 기록을 실제로 사용하지 않았다고 확정할 수는 없다. 답변이 기록과 유사하다는 사실도 내부 활용량을 측정하지는 못한다.

Synethos의 제품 계약에서는 제공 기록이 답을 직접 뒷받침하면 `records`와 해당 인용을 반환해야 했다. 따라서 이 사례에서 평가한 실패는 근거 분류·인용 정책의 미준수였다. 모델 내부의 근거 활용 정도는 측정하지 않았다. 유효하지 않은 인용 ID가 없다는 구조 검사는 인용 누락이나 주장별 근거 적합성을 확인하지 못했다.

## 실험 이후 관련 연구로 해석을 보강

사용자는 실험 종료 후 연구 중심 조사를 제시했다. 아래 문헌은 사례 작성 과정에서 원문을 확인한 해석 자료다. 당시 후보를 선택하거나 기각하기 전에 사용한 근거와는 시점을 구분한다.

| 연구 | 확인된 내용과 이 사례에서의 역할 |
|---|---|
| [Linguistic Nepotism](https://arxiv.org/html/2509.13930v3), ICML 2026 | 관련성을 통제한 다국어 근거에서 인용 언어 선호를 분석했고, 언어 선호가 관련성보다 우선되는 결과를 보고했다. 문서 언어에 따른 인용 대상 선택과 Synethos의 인용 누락은 서로 다른 관찰이다. |
| [On the Consistency of Multilingual Context Utilization](https://aclanthology.org/2025.mrl-main.15/), MRL 2025 | 다른 언어의 근거에서 정보를 추출하는 능력과 올바른 언어로 완전한 답변을 만드는 능력의 차이를 보여준다. |
| [XRAG](https://aclanthology.org/2025.findings-emnlp.849/), Findings of EMNLP 2025 | 응답 언어 준수와 여러 언어의 근거를 종합하는 추론의 어려움을 구분한다. |
| [Investigating Language Preference of Multilingual RAG Systems](https://aclanthology.org/2025.findings-acl.295/), Findings of ACL 2025 | 검색기와 생성기의 언어 선호를 별도로 분석한다. 검색된 근거와 생성 단계의 근거 활용을 구분하는 배경이다. |
| [Model Internals-based Answer Attribution](https://aclanthology.org/2024.emnlp-main.347/), EMNLP 2024 | 모델의 자기 인용이 실제 문맥 활용을 충실히 반영하지 못할 수 있음을 다룬다. 출력 인용과 내부 활용을 구분하는 근거다. |
| [Reasoning-Language Alignment](https://aclanthology.org/2026.oracle-main.29/), ORACLE 2026 | 독일어 질문·근거에 강제 독일어 추론을 맞추면 강제 프랑스어보다 나았지만 제약 없는 기본 영어 추론을 넘어서지는 못했다. 추론 언어를 바꾼 연구이며 이 실험의 출력 지침 변경과 조건이 다르다. |
| [Evaluating and Explaining Prompt Sensitivity](https://arxiv.org/abs/2608.18539), ICML 2026 | 작은 프롬프트 변화에 따른 내부 상호작용의 변동을 분석한다. 변경을 전체 출력 동작에서 검증해야 하는 배경이다. |

이 연구들은 언어를 근거 선택·문맥 활용·인용·추론과 함께 평가할 이유를 제공한다. Synethos의 특정 모델에서 한국어 우선 문구가 근거 활용을 안정화했다는 인과관계는 확인되지 않았다. 이 로컬 실험은 검색 결과를 고정했으므로 관찰 범위는 제공된 근거로 답변을 구성하는 생성 단계였다.

## 채택 기준을 충족하지 못해 기존 정책 유지

사용자는 언어 준수와 근거 기반 답변 품질을 함께 채택 기준으로 삼았다. 일부 실행에서 원하는 언어를 얻었어도 필요한 설명, 근거 분류와 인용이 일관되게 유지되지 않으면 운영 변경으로 수용하지 않았다.

모든 실험안을 폐기하고 기존 생성 정책을 유지했다. 기존 영어 언어 준수 문제는 남은 한계로 유지됐다. 당시 완료 보고에서는 Synethos 코드가 `main`의 `7505cfc`에 유지되고 작업 트리가 깨끗함을 확인했다. 사용자 요청으로 로컬 실험 파일 65개를 삭제했으며, 이 사례 작성에서도 원본 코드·응답 로그를 복원하지 않았다.

이 사례의 교훈은 다국어 RAG에서 언어를 전체 답변 품질과 함께 다루는 데 있다. 출력 언어를 맞춘 결과만으로 변경을 채택하지 않고, 설명의 충실도와 근거·인용 계약까지 확인했다.

## 검증 범위와 기록의 한계

언어 분류 후보와 지침 보강 후보는 질문별 1회였다. 우선 문구 제거 후보는 동일 영어 질문 6회였고 저장 Baseline은 영어 질문 1건이었다. 서로 다른 표본을 합쳐 성공률을 추정하거나, 언어 지침 변경이 모든 품질 차이의 원인이라고 확정하지 않는다. 일본어·아랍어·타갈로그어의 원어민 수준 유창성 평가는 수행되지 않았다.

공개 기록의 근거는 개발 대화에 남은 당시 실행 보고·일부 응답과 사용자의 미채택 결정, 위 외부 문헌이다. 원본 입력·응답·호출 원장과 원본 파일 해시는 현재 재검증할 수 없다. 문서의 링크·한영 대응·수정 범위 검증과 과거 모델 실험의 재현 여부를 구분한다.
